## 2. Leak-Free Architecture Guarantees

### A. Graph Target Leakage Elimination
- **Failure Mode in Naive Systems:** If candidate edge $(A, B)$ is present in the knowledge graph $G$ during validation of relation $(A, B)$, graph features trivially leak the target (e.g. shortest path length $= 1.0$, degree counts include the candidate edge itself).
- **Mathematical Invariance Guarantee:** In `GraphFeatureExtractor._without_candidate_edges(node_a, node_b)`, candidate edge $(A, B)$, reciprocal edge $(B, A)$, and self-loops $(A, A)$ are temporarily excised from $G$ via a deterministic Python context manager during feature extraction.
- **Verification:** Evaluated by `test_graph_leakage.py` across 9 regression tests, proving exact feature invariance whether the candidate edge has already been inserted or not.

### B. Cross-Document Data Leakage Elimination
- **Failure Mode:** Random record-level splitting leaks context between sentences from the same document across train, validation, and test sets.
- **Document-Isolated Split:** `SplitConfig(split_strategy="document")` partitions documents disjointly:
  $$\mathcal{D}_{\text{train}} \cap \mathcal{D}_{\text{val}} = \emptyset, \quad \mathcal{D}_{\text{val}} \cap \mathcal{D}_{\text{test}} = \emptyset, \quad \mathcal{D}_{\text{train}} \cap \mathcal{D}_{\text{test}} = \emptyset$$
- **Enforcement:** `SplitResult.assert_no_document_leakage()` strictly asserts disjoint sets prior to any model fitting.

## 3. Evidence Support & Lexical Grounding Rules

To ensure honest scientific terminology, the term **"entailment"** has been replaced with **"lexical evidence support"** and **"sentence grounding"**:
- Pattern-based extraction evaluates directional relational triggers, negation/contradiction boundaries, and contrastive clause markers (`while`, `although`, `whereas`).
- Hard rules prevent false matches across unrelated subordinate clauses or when assertions are explicitly negated.
- Complete backwards compatibility is retained for existing API clients and tests via aliasing.
